# AGENTS.md

## Project

malcolm — malcolm is a standalone Rust chaos engineering library for fault injection
and adversarial simulation. It provides realistic, mathematically-grounded
primitives for testing distributed systems, async services, and simulation
layers under real-world failure conditions.

Core capabilities:

- Seeded, deterministic fault replay (reproducible failures)
- Power-law and Pareto latency/failure distributions (not uniform random)
- Lyapunov sensitivity scoring (find where faults amplify most)
- Bifurcation threshold profiles (named tipping-point scenarios)
- Correlated noise generation: pink (1/f) and brown noise for realistic jitter
- Byzantine fault primitives (lies, partial responses, slow-correct)
- Network fault layer: partition, packet loss, latency spike, bandwidth cap
- Resource fault layer: memory pressure, CPU throttle, I/O degradation
- Clock fault layer: skew, freeze, jump (critical for consensus/sync logic)
- Cascade modeling: fault propagation across named topology nodes
- Full tracing integration: every fault emission is a structured event
- Zero unsafe code; no_std compatible core primitives

Designed to be pulled in as a dev-dependency or an optional feature flag
dependency in simulation builds. Plays nicely with tokio and is runtime-agnostic
at the core layer.

Optional interpretability layer via malcolm-lens: an LLM-backed crate that reads
ScenarioReport output and produces post-mortem narratives, anomaly flags, adaptive
scenario suggestions, and replay divergence explanations. Built on rig-core for
provider-agnostic LLM access — Ollama (local, default) and Anthropic both supported.
The LLM is strictly advisory and never on the fault injection path.

## Architecture: Modular

- Each module is self-contained with its own models, handlers, and storage
- Modules communicate through well-defined public interfaces
- Shared code goes in a `common/` or `shared/` module
- Prefer module-level encapsulation over cross-cutting layers

## Code style

- Language: rust
- Strategy: Complete — ship root fix end-to-end with tests and docs in the same task

## Rules

- Rust edition 2024, stable toolchain only — no nightly features.

- Zero .unwrap() or .expect() outside of tests; use thiserror for library errors, anyhow in examples.

- All public API surface must have rustdoc with at least one example block.

- Fault emissions must always produce a tracing event at the appropriate level.

- The core math primitives (distributions, noise generators, Lyapunov scorer) must be no_std compatible.

- Seeded RNG (rand::SeedableRng via SmallRng or ChaCha8Rng) is mandatory — no thread_rng() in library code.

- Tokio dependencies are optional features only; core crate must compile without tokio.

- Every fault type must implement a dry_run() mode that logs what would happen without actually injecting.

- Use Coraline (coraline_* MCP tools) for code navigation when exploring the codebase.

- No 'God' files — keep modules focused and single-purpose.

- All crates live under crates/: crates/malcolm-core, crates/malcolm, crates/malcolm-lens.

- Layer 1 — Domain (malcolm-core): pure math, value objects (FaultEvent, BifurcationProfile, Regime, distributions, noise). No I/O, no traits implying external dependencies. no_std enforced by crate boundary.

- Layer 2 — Assembly (malcolm): port traits (Fault, MalcolmClock, DistributionSampler) defined here, owned by this crate. Concrete adapters implement them. Scenario composition, topology, replay live here.

- Layer 3 — Infrastructure (malcolm-lens): LensProvider trait and OllamaLens/AnthropicLens adapters. Never on the fault injection path. Optional at compile time.

- Consumer-owned traits: port traits belong in the handler/assembly module, not in the adapter crate. Concrete impls (e.g. NetworkPartition) implement the trait but do not own or re-export it.

- Each port trait must be narrow — 1 to 3 methods covering only what the consuming module actually calls.
